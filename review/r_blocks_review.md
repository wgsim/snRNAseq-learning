## (1) nebula `group_cell` NULL 대비

**패키지 확인 사항**
- `group_cell()` 소스에서 `id <- as.character(id); levels <- unique(id); id <- as.numeric(factor(id, levels = levels))` 후 `is.unsorted(id) == FALSE`이면 `"The cells are already grouped."`를 출력하고 `NULL`을 반환합니다. 레벨이 정렬 순서가 아니라 **등장 순서**라서, 한 환자의 세포가 연속 블록이면 환자 순서와 상관없이 NULL이 됩니다.
- NULL이 아닐 때 반환하는 값은 `list(count = count[, o], id = id[o], pred = pred[o, ], offset = offset[o])` (`o <- order(id)`) 꼴입니다. NULL일 때는 이미 순서가 `o`와 같으므로 원본을 그대로 쓰면 정확히 같은 입력이 됩니다.
- `nebula()` 내부도 같은 방식(`as.character → unique 레벨 → as.numeric(factor)`)으로 `id`를 다시 인코딩하고 `is.unsorted(id)`이면 오류를 냅니다. 따라서 폴백에 원래의 `meta_df$patient_id`(문자/요인)를 넘겨도 문제없습니다. 숫자 코드로 바꿔 넘길 필요는 없습니다.
- 인자 순서(count/id/pred/offset)는 `group_cell`과 `nebula`가 같고, 폴백 리스트의 이름도 같습니다.

**offset 처리**
- `?nebula`: "offset: A vector of the scaling factor. The values must be strictly positive. If not specified, a vector of all ones will be generated by default." 곧 `offset`은 **로그가 아닌 원 스케일의 양수 배율값**(라이브러리 크기 또는 size factor)이고 내부에서 로그를 취합니다. `group_cell`도 `offset <= 0`이면 `Some elements in the scaling factor are not positive.`로 중단합니다.
- 따라서 `meta_df$total_counts`(세포별 총 UMI)는 올바른 단위입니다. 로그를 취한 값(예: `glmmTMB`의 `offset(log_depth)`용 값)을 넘기면 틀립니다. 같은 챕터의 주석 `# 또는 size factor`도 맞습니다.
- 주의 한 가지: `total_counts`가 0인 세포가 있으면 `group_cell`과 `nebula`가 모두 중단하므로, 블록 앞에서 QC로 제거돼 있어야 합니다(본문의 코호트는 필터링된 세포이므로 모순 없음).
- 챕터 04의 `neb_data` 블록(`04_GLMM…md:317–327`)이 이미 동일한 폴백을 쓰고 있어 표기가 일관됩니다.

**본문과의 충돌:** 없습니다. 3단계 주석은 "group_cell은 같은 환자의 세포를 연속 인덱스로 재정렬한다"인데, 폴백 주석이 그 보완이 됩니다.

**최종 코드 (3단계 교체)**
```r
# 3. 세포들을 Donor ID별로 정렬 및 그룹화 (NEBULA 필수 전처리)
# group_cell 함수는 블록 대각 구조를 위해 동일 환자의 세포를 연속 인덱스로 재정렬함
data_grouped <- group_cell(
  count   = counts_mat,
  id      = meta_df$patient_id,
  pred    = design_mat,
  offset  = meta_df$total_counts # 양수 배율값(라이브러리 크기 또는 size factor); 로그 값이 아님
)
# 이미 donor별로 연속 배치되어 있으면 group_cell()은 NULL을 반환하므로 원본을 그대로 사용
if (is.null(data_grouped)) {
  data_grouped <- list(count  = counts_mat,
                       id     = meta_df$patient_id,
                       pred   = design_mat,
                       offset = meta_df$total_counts)
}
```

**후속 제안(같은 챕터):** 5.2 Python 블록(`05_FAST…md:353–368`)의 `r_grouped = nebula_r.group_cell(...)` 뒤에서 `r_grouped.rx2("count")`를 쓰는데, 이미 정렬된 입력이면 `group_cell`이 R의 `NULL`을 반환해 rpy2에서 같은 실패를 합니다. 파이썬 쪽도 `if r_grouped is ro.NULL:`(또는 `rpy2.rinterface.NULL`) 분기에서 `counts`, `donor_ids`, `design_mat`, `offset`을 그대로 쓰도록 같은 폴백이 필요합니다. 이번 eng 실행 범위에는 없었으므로 미검증입니다.

## (2) Milo `plotNhoodGraphDA` 레이아웃

**패키지 확인 사항**
- `plotNhoodGraph(x, layout = "UMAP", …)`가 기본값이고, `layout`이 문자열이면 `reducedDims(x)`에 그 이름이 없으면 중단합니다(eng 로그의 오류와 일치). 따라서 UMAP이 없으면 실패하는 것은 맞습니다.
- 레이아웃의 역할은 이웃 노드의 **그림상 좌표**뿐입니다(이웃 좌표 = 이웃 소속 세포의 레이아웃 좌표 평균). DA 통계는 `buildGraph(reduced.dim=)` → `makeNhoods(reduced_dims=)` → `countCells` → `testNhoods`에서 모두 끝나므로, UMAP 선택은 `logFC`, `PValue`, `SpatialFDR`에 영향을 주지 않는 표시용입니다. 그림의 해석(이웃들이 가까운가)만 UMAP 품질에 좌우됩니다.
- `scater::runUMAP(x, ..., dimred, n_dimred, name = "UMAP")`: `dimred`는 기존 reducedDim 이름이고, `n_dimred`를 주지 않으면 **모든 차원**을 쓰며, 정수 하나이면 앞의 그만큼의 열만 씁니다. 결과는 `reducedDim(x, "UMAP")`에 저장됩니다. UMAP 자체는 난수에 의존하므로 `set.seed`가 필요합니다.

**본문과의 정합성**
- 본문 3단계는 `buildGraph(…, d = 30, reduced.dim = "HARMONY")`입니다. UMAP을 HARMONY 위에서 만드는 것은 그래프와 같은 잠재 공간이므로 논리적으로 맞습니다. 다만 그래프는 앞 30차원만 쓰는데 `runUMAP`이 `n_dimred` 없이 전 차원을 쓰면 그래프와 레이아웃의 공간이 다를 수 있으므로 `n_dimred = 30`을 맞추는 것이 일관됩니다(HARMONY가 30차원 미만이면 `min(30, ncol(reducedDim(sce,"HARMONY")))`).
- 코드 주석은 "PCA 및 Harmony 보정 좌표가 포함된 snRNA-seq 객체"입니다. 사용자가 이미 `UMAP`을 갖고 있으면 새로 계산하지 않도록 조건을 두는 쪽이 안전합니다(덮어쓰기 방지).
- 위치: `Milo(sce)`가 `reducedDims`를 복사하므로 `Milo()` 앞에 두는 제안이 맞습니다. `Milo` 객체 위에서 실행해도 동작하지만 순서를 바꿀 이유가 없습니다.

**최종 코드 (1단계 교체)**
```r
# 1. SingleCellExperiment 객체로부터 Milo 객체 초기화
# sce: PCA 및 Harmony 보정 좌표가 포함된 snRNA-seq 객체
# plotNhoodGraphDA/buildNhoodGraph의 기본 layout은 reducedDim "UMAP"이다. UMAP이 없으면 표시 단계(9단계)에서 오류가 난다.
# UMAP은 이웃 그래프 좌표 표시용일 뿐 DA 통계(logFC, PValue, SpatialFDR)에는 영향을 주지 않는다.
if (!"UMAP" %in% reducedDimNames(sce)) {
  set.seed(42)
  sce <- runUMAP(sce, dimred = "HARMONY", n_dimred = 30)   # buildGraph의 d = 30과 같은 공간
}
milo_obj <- Milo(sce)
```

**(2a)** 5단계 `countCells(…, sample = "sample_id")`는 `samples = "sample_id"`로 바꿉니다. 현재 시그니처가 `countCells(x, samples, meta.data = NULL)`이고 부분 일치로 동작하고 있어 결과는 같지만, 정식 인자명이 안전합니다.
```r
milo_obj <- countCells(
  milo_obj,
  meta.data = as.data.frame(colData(milo_obj)),
  samples   = "sample_id"
)
```

## (4) 블록 4 Hessian 경고 안내 — apply

```r
    lrt_model_comp <- anova(fit_ri, fit_rs)

    # "non-positive definite Hessian" 경고를 내고 LRT 행이 NA가 될 수 있다.
    # 이 경우 랜덤 기울기 모형은 해석하지 말고 fit_ri(랜덤 절편)를 사용한다.
```
